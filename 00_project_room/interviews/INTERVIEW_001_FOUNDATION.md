# Interview 001: Foundation

Status: Partially answered by the project owner on 2026-06-27.

Purpose: clarify the first milestone before GitHub issues, product planning, or model work.

## Questions

1. What is the first useful artifact we should produce?
   - Options: source inventory, searchable database, editorial sample, frontend demo, model/RAG prototype, publishing plan, something else.

2. What would count as "done" for the first 2-4 week milestone?
   - Be concrete: file, demo, dataset, schema, sample chapter, working search, or reviewed plan.

3. Who is the first real user?
   - Internal team, professional chef, culinary researcher, advanced home cook, publisher/funder, Italian Builders community, or another group.

4. What is private, open, or undecided?
   - Raw PDFs, OCR text, structured recipe data, editorial notes, code, prompts, model weights, app.

5. What source material can we legally and ethically use first?
   - Public domain only, family-owned scans, private research only, or unclear.

6. What should be explicitly out of scope for the next 2-4 weeks?
   - Examples: fine-tuning, polished frontend, public launch, book publishing, classes, monetization.

7. What language should project docs use?
   - English only, Italian only, bilingual, or English with Italian culinary/source terms preserved.

8. Who is on the team and what should each person own?
   - Names, skills, availability, and whether they should work through GitHub issues, Slack, or direct docs.

9. What is the strongest reason this project should exist?
   - Preservation, research, cultural value, product opportunity, model/data advantage, fundraising, education, or something else.

10. What would make you kill or pause the project?
    - Lack of data, rights risk, weak user interest, no technical differentiation, too much editorial labor, team bandwidth.

## Answers Received

### 1-2. First Artifact And 2-4 Week Milestone

The project owner wants the first 2-4 week milestone to be a live website with basic functionality:

- inventory
- database
- frontend
- maybe an AI feature, but not necessarily

The project should be more like a digital library first. It should not yet focus on publishing, editorial modernization, standardized measurements, or creating new versions of books.

The project owner requested several concrete V1 product options so the team can choose what is feasible and worth building.

### 3. First Real Users

First users:

- internal team members
- home cooks
- Italian Builders community
- public visitors who navigate to the web app

### 4-5. Open Source And Public Use

The project owner's intent is open source. Data, PDFs, model outputs, model weights, and code should be public where legally safe.

More specificity is needed around copyright, public domain status, PDF hosting, OCR text, model outputs, and model weights.

### 6. Out Of Scope

Out of scope depends on which V1 product option the team chooses. For now, the clearest exclusions are:

- publishing
- editorial creation of new standardized recipe versions
- broad measurement normalization

### 7. Documentation Language

Repo docs should be in English.

### 8-10. Still Open

- Team member roles and ownership.
- Strongest reason the project should exist.
- Kill/pause criteria.
